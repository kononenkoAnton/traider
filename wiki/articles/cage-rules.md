# Правила клетки

Клетка это чистая логика над состоянием счёта, без сети. Она одна для агента, для «обезьян» и для тестов. Модель не может отправить заявку в обход неё.

Значения по умолчанию владелец может изменить до старта прогона. После старта они заморожены.

## Правила

| Правило | По умолчанию |
|---|---|
| Вселенная | Состав S&P 500 плюс широкие и секторные ETF, только то, что Alpaca разрешает покупать долями; без плечевых и обратных ETF. Список фиксируется при старте |
| Направление | Только покупка. Без плеча: покупка не больше свободных денег |
| Размер позиции | Не больше 20% капитала в одном тикере, не меньше $20 в заявке |
| Стоп | Обязателен, от 3% до 15% ниже текущей цены. Один стоп на тикер |
| Докупка | Стоп новой покупки не ниже действующего стопа по этому тикеру |
| Повторная покупка | Тикер, закрытый сегодня, сегодня купить нельзя |
| Суммарный риск | Сумма (количество × (цена − стоп)) по всем позициям не больше 8% капитала |
| Покупок за сессию | Не больше 3. Продажи не ограничены: снижать риск можно всегда |
| Прогнозы | Покупки отклоняются, пока не записаны прогнозы по панели и по покупаемому тикеру |
| Бюджет модели | $2 и 40 ходов на сессию, дальше цикл обрывается |

Доллары потолка свои у каждой модели ([[model-and-budget]]).

## Коды отказа

Проверки идут в этом порядке, агент получает первый сработавший отказ с числами. Границы включительные: стоп ровно в 3% или 15% ниже цены, позиция ровно 20% капитала, заявка ровно $20 принимаются.

| Код | Когда срабатывает |
|---|---|
| `bad_request` | Сумма или стоп не являются конечным положительным числом |
| `not_in_universe` | Тикера нет во вселенной |
| `no_price` | Для тикера нет цены |
| `no_panel_forecasts` | Прогнозы по панели ещё не записаны |
| `no_symbol_forecast` | Нет прогноза по покупаемому тикеру |
| `too_many_buys` | Лимит покупок за сессию исчерпан |
| `rebuy_same_day` | Тикер закрыт сегодня, повторная покупка запрещена |
| `order_too_small` | Заявка меньше минимума $20 |
| `stop_out_of_range` | Стоп не лежит в диапазоне от 3% до 15% ниже цены |
| `stop_below_existing` | Стоп докупки ниже действующего стопа по тикеру |
| `position_too_large` | Позиция после покупки больше 20% капитала |
| `not_enough_cash` | Заявка больше свободных денег |
| `open_risk_too_high` | Суммарный риск после покупки больше 8% капитала; новая покупка считается со своим стопом на всю позицию |

Подъём стопа отклоняется кодами `bad_request`, `no_position`, `no_price`, `stop_not_higher` (новый стоп не выше действующего) и `stop_out_of_range`.

## Битые числа

Котировка, которая не является конечным положительным числом, не используется: позиция оценивается по цене входа, как при отсутствии котировки. Если нечисловое значение в самом счёте (деньги, пик капитала, количество, цена входа или стоп позиции), покупка и подъём стопа отклоняются с кодом `bad_request`, а расчёт капитала, HP и гибели выбрасывает ошибку и не отвечает ни «жив», ни «погиб». Все сравнения с лимитами написаны так, что неопределённый результат даёт отказ.

## Как работает отказ

Отказ клетки возвращается агенту с причиной, чтобы он мог исправить заявку. Каждое решение клетки и каждый ответ брокера сразу дописываются в журнал заявок. Остаток лимитов считается из журнала, а не из памяти процесса, поэтому сбой посреди сессии лимиты не обнуляет.

## Стоп после покупки

После исполнения покупки стоп у брокера ставит код, не агент ([[stops]]). Нижняя граница потери задаётся полом капитала ([[hp-floor]]).

## Почему лимиты в коде

Цель проекта: максимум свободы в решениях, ноль свободы в рисках ([[experiment-question]]). Отказы клетки по причинам попадают в отчёт ([[analytics-page]]).
