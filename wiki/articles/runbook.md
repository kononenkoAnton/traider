# Порядок действий владельца

Шаги по порядку, от установки до аварийной остановки. Код читать не нужно. Все команды запускаются из каталога проекта. Правила о ключах: [[setup-and-keys]]; расписание: [[schedule-and-hosting]].

## 1. Установка

```
uv sync
uv run pytest -q
```

Тесты идут без ключей и без сети. Должны пройти все; тесты с пометкой `paper` по умолчанию не запускаются.

## 2. Счёт Alpaca

1. Создайте paper-счёт Alpaca с балансом $1000, без позиций и без открытых заявок. Стандартный paper-счёт держит $100 000: его баланс нужно сбросить на $1000 в настройках счёта.
2. Этим счётом пользуется ровно один прогон. Второй прогон на тех же ключах программа не запустит, а позиция, которую прогон не покупал, останавливает всю его работу со счётом ([[accounts]]).
3. Скопируйте `.env.example` в `.env` и впишите paper-ключи под именами `ALPACA_API_KEY` и `ALPACA_SECRET_KEY`.
4. Живых ключей (`ALPACA_LIVE_API_KEY`, `ALPACA_LIVE_SECRET_KEY`) в `.env` во время пилота нет.

Если на счёте при первом тике прогона будет не $1000 (допуск 2%), позиции или открытые заявки, тик по `opus-a` даст `error` с найденными числами и ничего не отправит; после исправления счёта следующий тик пройдёт.

## 3. Anthropic Console

1. Создайте API-ключ и впишите его в `.env` под именем `ANTHROPIC_API_KEY`.
2. Поставьте месячный лимит трат (spend limit) в настройках организации.
3. Выключите автопополнение (auto-reload). Только тогда запросы встанут, когда кредиты кончатся, а не спишут деньги с карты.

Лимит трат в Console это единственная жёсткая граница расхода; потолки программы ([[model-and-budget]]) её не заменяют.

## 4. Проверка ключей

В часы торгов США:

```
uv run pytest -m paper -q
```

Тест покупает SPY на $20, проверяет стоп и закрывает позицию на paper-счёте. После него на счёте остаётся около $1000 без позиций и заявок; это в пределах допуска шага 2.

## 5. Вселенная бумаг

```
uv run python tools/build_universe.py --alpaca
git diff data/universe.txt
```

Флаг `--alpaca` оставляет только бумаги, которые Alpaca разрешает покупать дробно. Просмотрите разницу: пропавшие и добавленные тикеры должны быть объяснимы ([[universe]]). Если всё в порядке, зафиксируйте файл в git.

## 6. Старт пилота

1. `cp experiment.example.toml experiment.toml`
2. В `experiment.toml` задайте `experiment` (имя, например `pilot-1`) и оставьте `pilot = true`, `mode = "paper"`.
3. `uv run traider start experiment.toml`

Команда печатает каталоги прогонов (`runs/<эксперимент>/<участник>`) и худший расход: у образца конфига «Худший расход: $7.55 в торговый день, $158.55 за 21 торговый день», и строку о том, что жёсткая граница это лимит трат в Console. Если в `runs/` уже есть незавершённый прогон на Alpaca, старт откажет и назовёт его.

4. `uv run traider status`: по строке на участника, статус `active`, сессий 0 из цели.

## 7. Один тик вручную

В часы торгов, после 10:00 по Нью-Йорку (начало окна сессии):

```
uv run traider tick
```

Здоровый результат: по строке на участника вида `2026-12-01 10:05 pilot-1/haiku: session ok $0.31`. Статус `ok` значит, что агент закончил сам; `cap`, что упёрся в потолок ходов, денег или 20 минут. До 10:00 действие `safety` (только проверка HP и стопов).

Дальше проверьте файлы одного прогона, например `runs/pilot-1/haiku/`:

- `ticks.jsonl`: новая строка с `action` `session`, `status` `ok`, `error` пустой, `equity`, `floor` и `hp` числами (у нового счёта 1000, 850 и 150), `unpriced` пустой список.
- `sessions/<сегодня>.json`: `status` `ok`, `stop` `finished`, непустой `journal`, `errors` пустой список, `snapshot_symbols` близко к числу бумаг вселенной, `fallback_used` `false`, `cost` не выше потолка участника.

Поля файлов: [[run-files]].

## 8. Расписание

1. Поставьте задание launchd по шагам из [[schedule-and-hosting]] (копия шаблона в `~/Library/LaunchAgents/`, `launchctl bootstrap`).
2. Mac не должен засыпать в часы торгов (9:30–16:00 по Нью-Йорку). Либо в «Системных настройках» → «Аккумулятор» (или «Экономия энергии») → «Параметры» включите «Предотвращать автоматический переход в режим сна при подключении к сети, если дисплей выключен» и держите Mac на зарядке, либо на время торгов держите открытым терминал с `caffeinate -i -s` (остановка Ctrl+C).
3. Задание из `~/Library/LaunchAgents/` работает, только пока вы вошли в систему. После перезагрузки войдите в свою учётную запись, иначе тиков не будет.

## 9. Ежедневный взгляд

```
uv run traider status
tail -50 logs/tick.log
```

Что значат действия в строках тика:

- `error`: тик по участнику не прошёл. Прочтите текст. Сеть или API: следующий тик повторит сам. «на одном счёте Alpaca (paper) больше одного незавершённого прогона: <эксперимент/участник, …>; брокер не создавался, ничего не отправлено. Оставьте один прогон (finished, dead или каталог вне runs/)» (вместо `paper` может стоять `live`) или «RuntimeError: на счёте Alpaca позиции, которых нет у этого прогона: <тикеры>; счёт не принадлежит одному прогону, ничего не отправлено»: на счёте торгует кто-то ещё, уберите лишний прогон (шаг 11) или разберитесь с позицией руками. «Конфиг больше не совпадает с режимом и брокером»: шаг 12.
- `unpriced`: у удерживаемой бумаги ещё нет сегодняшней цены (нормально утром до первой сделки). Сессия ждёт, гибель в такие тики не решается, стопы проверяются. Если держится весь день, проверьте тикер (не снят ли с торгов).
- `invalid`: конфиг прогона правили после старта. Сессий нет, проверка HP и стопы работают. Решите, продолжать ли прогон (шаг 12).
- `died`: капитал опустился ниже пола, позиции проданы, прогон окончен навсегда ([[hp-floor]]). Ничего делать не нужно; это результат эксперимента.

Пропущенные дни (`missed`) и сбойные сессии видны в `traider status` и в `sessions/`.

Отчёт и страница. После дня сессий тик сам собирает отчёт; страница лежит в `runs/<эксперимент>/dashboard.html` и открывается с диска двойным щелчком ([[analytics-page]]). Собрать вручную: `uv run traider report` (все эксперименты) или `uv run traider report <эксперимент>`; команда печатает пути файлов. Статья вики с результатами пишется только с `--wiki`: `uv run traider report <эксперимент> --wiki wiki` на машине разработки, где лежат вики и копия `runs/`; на Mac mini с `--wiki` не запускайте, чтобы отслеживаемые файлы не менялись. Сбой отчёта виден одной строкой в `logs/` и тик не затрагивает.

## 10. Не запускайте тик руками при загруженном расписании

Пока задание launchd загружено, `traider tick` вручную не запускайте: ручной запуск и расписание спорят за замок `runs/.tick.lock`, и тот, кто пришёл вторым, молча ничего не делает. Для ручного тика сначала снимите задание (`launchctl bootout gui/$(id -u)/com.traider.tick`), потом поставьте снова.

## 11. От пилота к официальному прогону

1. Уберите каталог эксперимента пилота из `runs/` (например, `mv runs/pilot-1 archive/`) или дождитесь, пока прогон `opus-a` пилота станет `finished`.
2. Сбросьте paper-счёт Alpaca на $1000 без позиций и заявок.
3. Задайте новое имя эксперимента, `pilot = false`, поправьте потолки по итогам пилота ([[pilot]]).
4. `uv run traider start experiment.toml`, затем шаги 7 и 8.

## 12. Если сработала проверка режима и брокера

Сообщение «конфиг больше не совпадает с режимом и брокером, записанными при старте прогона; брокер не создавался, ничего не отправлено» значит: в `config.json` прогона `mode` или `broker` уже не те, что записаны в `state.json` при старте (`started_with`), или записи нет. Тик по этому прогону не создаёт брокера, поэтому не проверяет ни HP, ни стопы, и ставит статус `invalid`.

Статус остаётся `invalid` и после того, как конфиг вернули: программа сама его не снимает. Чтобы вернуть прогон:

1. Снимите расписание (`launchctl bootout gui/$(id -u)/com.traider.tick`).
2. Проверьте счёт руками: у Alpaca позиции и стоп-заявки, у встроенного счёта `traider status`.
3. Верните в `config.json` прежнее значение `mode` или `broker` ровно так, как было (каталог `runs/` не в git, поэтому нужна своя копия или точная обратная правка). Контрольная сумма должна сойтись: `shasum -a 256 runs/<эксперимент>/<участник>/config.json` совпадает с содержимым `config.sha256` рядом.
4. В `state.json` прогона проверьте, что `started_with` равен режиму и брокеру конфига, и замените `"status": "invalid"` на `"status": "active"`.

   Если записи `started_with` в `state.json` нет, впишите её руками в верхний уровень объекта, рядом с `status`. Для бумажного прогона на встроенном счёте:

   ```
   "started_with": {"mode": "paper", "broker": "sim"}
   ```

   Для прогона на Alpaca:

   ```
   "started_with": {"mode": "paper", "broker": "alpaca"}
   ```
5. `uv run traider status`: статус `active`, пометки о контрольной сумме нет. Поставьте расписание снова.

Если конфиг вернуть нельзя, прогон считается испорченным: начните новый.

## 13. Аварийная остановка

1. Снимите расписание: `launchctl bootout gui/$(id -u)/com.traider.tick`. Позиции при этом остаются открытыми.
2. Стоп-заявки Alpaca действуют только до закрытия дня; без тика их никто не вернёт, и со следующего дня позиции `opus-a` стоят без стопов.
3. Закрыть позиции Alpaca руками: в веб-интерфейсе Alpaca, в разделе позиций paper-счёта, закройте каждую позицию (Close position) и отмените оставшиеся заявки. После ручных продаж прогон `opus-a` не продолжайте: его журнал о них не знает.
4. Встроенные счета денег не держат: их позиции просто остаются в файлах. Стопы по ним не проверяются, пока тик стоит; когда тик вернётся, сверка пройдёт по минутным свечам с последней проверки и исполнит задетые стопы задним числом ([[stops]]).
