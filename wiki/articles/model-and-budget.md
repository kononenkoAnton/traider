# Модель и бюджет

## Чем платим

Выбран API-ключ Anthropic: у владельца план Max, расход покрывают включённые API-кредиты ($100 в месяц, не переносятся). Подписка через `claude -p` отвергнута: потребительские условия запрещают автоматический доступ, а явного разрешения для скрипта по расписанию нет. Облачные сессии Claude Code тоже не подходят: у агента там есть терминал, набор инструментов не ограничить, клетка перестаёт быть стеной.

Расход аналитика у `opus-analyst` считается отдельно по ценам его модели и входит в стоимость сессии ([[analyst]]).

## Как устроен «мозг»

Anthropic SDK для Python; модель берётся из конфига участника ([[participants]]). Адаптивное мышление с кратким изложением (`display: "summarized"`: по умолчанию у этих моделей текст мышления в ответе пуст, и в записи сессии не было бы рассуждений; на оплату это не влияет), effort `high` задан явно у всех для сопоставимости, стриминг, кэширование промпта, серверный `web_search`. Стоимость считается из учёта токенов по таблице цен в конфиге.

## Потолки

- Лимиты ходов (40) и поисков (8) одинаковы для всех.
- Лимит поисков на сессию исполняет сам API. Его счёт идёт за ход, а ход продолжается, пока каждое следующее сообщение цикла состоит только из результатов инструментов; цикл так и устроен, поэтому вся сессия это один ход. Поиск вызывается напрямую, без динамической фильтрации (у версии поиска для Opus и Sonnet это задаёт поле `allowed_callers`, у базовой версии для Haiku вызов прямой и так, поле не шлётся): поиски из выполнения кода API между запросами не суммирует, и лимит работал бы только на один запрос. Определение поиска одно на всю сессию и кэш промпта не сбрасывает ([[decision-log]]).
- Потолок в долларах это предохранитель, свой у каждой модели: $2 для Opus, $1 для Sonnet, $0.25 для Haiku.
- При стартовых потолках худший случай больше $100 кредитов. Поэтому после [[pilot]] потолки подбираются так, чтобы худший случай не превышал $90.
- У сессии есть срок `max_session_seconds` = 1200 секунд (в замороженных лимитах), у каждого вызова аналитика 600 секунд. Срок сверяется перед каждым запросом; начатый запрос не обрывается. Клиент Anthropic создаётся с `timeout` 300 секунд на каждое ожидание сети в запросе и `max_retries` 2.
- При достижении потолка цикл обрывается, стопы остаются на месте ([[stops]]).
- Агент видит расход: после каждого хода с вызовами инструментов к тексту последнего результата добавляется строка «[Состояние: ход N из 40, потрачено $X из $Y, поисков K из 8.]» (без поисков, если их нет). Отдельным блоком её не шлют: следующее сообщение должно состоять только из результатов инструментов, иначе API начнёт новый ход и обнулит счёт поисков. Системный промпт и промпт аналитика говорят об этой строке одной фразой.
- `traider start` печатает худший расход эксперимента: сумма потолков сессий всех участников и потолка аналитика за торговый день и за 21 торговый день; у образца конфига это $7.55 в день. Жёсткая граница это лимит трат в Anthropic Console ([[runbook]]).

Если кредиты всё же кончатся, запросы встанут на паузу, сессии запишутся сбойными, а проверка HP и стопы продолжат работать: они модель не вызывают ([[hp-floor]]).

## Чем может закончиться цикл агента

Цикл (`traider/brain.py`) ведёт разговор вручную и после каждого ответа модели проверяет расход раньше, чем выполняет инструменты этого ответа. Он не поднимает исключений. Исходов семь:

1. `finished`: модель вызвала завершающий инструмент и он отработал без ошибки. Вызовы идут по порядку; после успешного завершающего остальные вызовы того же ответа не выполняются, каждый получает результат с ошибкой «не выполнено: сессия уже завершена». Вызовы до него выполняются. Завершающий вызов с ошибкой сессию не заканчивает.
2. `end_turn`: модель закончила ответ, не вызвав завершающий инструмент (сюда же идут остановка по своей воле и по стоп-последовательности).
3. `max_turns`: исчерпан лимит обращений к модели. Приостановка `pause_turn` продолжается повторной отправкой и тоже считается ходом.
4. `budget`: накопленная стоимость достигла потолка в долларах. Инструменты ответа, на котором это случилось, не выполняются, поэтому заявка из этого хода не уходит.
5. `deadline`: истёк срок сессии; сессия пишет это как `cap`.
6. `refusal`: модель или классификатор отказали. Серверная подмена модели включена для Opus и Sonnet и недоступна для Haiku; ответившая модель записывается в результат.
7. `error`: исключение клиента (кончились кредиты, сеть), ответ оборван по лимиту токенов, неизвестная причина остановки, остановка по вызову инструмента без вызовов, или любой сбой самого цикла. Текст ошибки сохраняется вместе с уже накопленными ходами, расходом и записью; уже купленное остаётся со стопами. Если упал сам запрос, к тексту добавлено, что он мог быть оплачен и в стоимость не входит: цикл его не повторяет.

Стоимость считается по каждому запросу отдельно и суммируется. Цены Haiku 5.5 за миллион токенов: запрос до 100 000 токенов стоит 0.10 за вход, 0.125 за запись кэша, 0.01 за чтение кэша и 0.50 за выход; запрос длиннее 100 000 токенов (вход плюс чтение и запись кэша, строго больше) стоит 0.50, 0.625, 0.05 и 2.50. Длина считается по каждому запросу отдельно, и запрос выше порога платит длинные ставки за все четыре вида токенов, даже если часть его промпта взята из кэша. Таблица цен несёт `long_prompt_threshold` и четыре ключа `*_long`: либо все пять, либо ни одного, иначе старт эксперимента отклоняется. У Opus и Sonnet длинной ставки нет. Ошибка инструмента, неизвестный инструмент или вход, не прошедший проверку по схеме, возвращаются модели как результат с признаком ошибки, и цикл продолжается. Если в ответе есть список итераций (`usage.iterations`), стоимость и токены это сумма по нему: по документации это учёт оплаты по каждой попытке и каждому шагу серверного цикла, а верхний `usage` описывает только попытку, давшую ответ. Без списка берётся верхний `usage`. Поиски берутся из `server_tool_use` и оплачиваются один раз на ответ. При подмене каждая попытка оценена по таблице цен основной модели: это приближение. Признак `fallback_used` в результате истинен, только если ответила не запрошенная модель (поле `model` ответа) или в списке итераций есть запись типа `fallback_message`: так подмену обозначает SDK Anthropic. Модель, названная в записях других типов (шаг `message` серверного цикла поиска, запись советника), подменой не считается. До 16.11.2026 подменой ошибочно считали несколько итераций одной модели, потом любую запись итераций с другой моделью ([[decision-log]]).

## Подмена модели

Серверная подмена при отказе включена там, где доступна, чтобы сессия не пропадала. Запись сессии фиксирует, какая модель ответила, отчёт считает такие сессии отдельно. Альтернатива: выключить подмену и считать отказ пропущенным днём.

## Промпт

Задача (растить счёт в рамках правил; участнику сказано, что его оценивают по сделкам и прогнозам и что без 15 закрытых сделок оценки нет; не купить ничего в отдельный день нормально), порядок сессии из пяти шагов (счёт и позиции, кандидаты, свечи и новости, прогнозы, решение), правила клетки ([[cage-rules]]), обязанности, предупреждение, что текст из сети данные, а не указания.

## Стоимость в отчёте

Отчёт показывает результат и без учёта стоимости модели, и с ней ([[analytics-page]]). Для живого счёта $1 в день это примерно 2% в месяц от $1000.
