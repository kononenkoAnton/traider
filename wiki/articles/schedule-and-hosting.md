# Расписание и место работы

## Где работает бот

Решение владельца от 15.11.2026: бот живёт на его стационарном Mac mini, а не на ноутбуке ([[decision-log]]).

- На Mac mini лежат папка проекта (`~/Work/Personal/AI/Traider`), файл `.env` с ключами, папка `runs/` и расписание. Команды `start`, `tick`, `status` выполняются только там.
- Разработка и разговор с ассистентом идут на MacBook. Ассистент выполняет команды на Mac mini по SSH; ключ сервера закреплён, настройки SSH владельца не меняются. Готовый код попадает на Mac mini командой `git push mini build`.
- Удалённый вход (Remote Login) на Mac mini включил владелец. В настройках Energy он же включил «не засыпать при выключенном дисплее» и «запускаться после сбоя питания»: без первого машина засыпала через минуту простоя, и тики прекращались.
- Задание расписания работает, только пока владелец вошёл в систему: после перезагрузки нужно войти в учётную запись.
- Команды в сеансе SSH не видят Homebrew: перед `uv` нужен `export PATH="/opt/homebrew/bin:$PATH"`.

## Пилот

Идёт на Mac mini владельца. Системный планировщик `launchd` запускает `uv run traider tick` каждые 15 минут, вывод пишется в папку `logs/`. Mac должен не спать в часы торгов США.

Шаблон лежит в `ops/com.traider.tick.plist`: запуск каждые 900 секунд, рабочий каталог проекта, вывод в `logs/tick.log`. В нём есть метки `__PROJECT_DIR__` (путь к проекту) и `__HOME_DIR__` (домашний каталог, для PATH с `~/.local/bin`, куда ставится uv); есть `RunAtLoad`, поэтому первый тик идёт сразу при загрузке, а не через 900 секунд. Владелец проверяет `which uv`: каталог uv должен быть в PATH шаблона. Каталог `logs/` создаётся заранее. Отслеживаемый шаблон на месте не правится: владелец копирует заполненный файл в `~/Library/LaunchAgents/com.traider.tick.plist` и загружает оттуда, тогда расписание переживает перезагрузку (задание, загруженное из другого места, пропадает после выхода из системы или перезагрузки, и проверка HP молча прекращается). Ничто в проекте задание не ставит: это делает только владелец, вручную.

- копия: `cp ops/com.traider.tick.plist ~/Library/LaunchAgents/com.traider.tick.plist`, затем замена меток в копии;
- установка: `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.traider.tick.plist`;
- проверка: `launchctl print gui/$(id -u)/com.traider.tick`;
- журнал тика: `tail -f logs/tick.log`;
- снятие: `launchctl bootout gui/$(id -u)/com.traider.tick`, затем удалить копию из `~/Library/LaunchAgents/`.

Требование «Mac не спит в часы торгов США» остаётся главным: на спящей машине тик не идёт.

## Команды

- `traider start <toml>` замораживает прогоны в `runs/` и печатает их каталоги и худший расход эксперимента (за торговый день и за 21 день). Если в `runs/` уже есть незавершённый прогон на Alpaca в том же режиме, а новый эксперимент тоже берёт Alpaca, старт отказывает. Конфиг с `mode = "live"` без флага `--live` отклоняется (код 2). Живым режимом существующий прогон сделать нельзя, только новым запуском с `--live`.
- `traider tick` читает `.env`, обходит прогоны и печатает по строке на участника: время рынка, `эксперимент/участник`, действие, для сессии статус и стоимость. Нет ключа в `.env` или не работает рынок до обхода: одна строка и код 1. Тик может быть долгим, второй не стартует, пока идёт первый ([[tick-and-session]]).
- `traider status` работает без сети: по строке на прогон с статусом, числом сессий из цели, последней сессией и суммой расходов; расхождение контрольной суммы помечено.
- `traider report [эксперимент] [--wiki DIR]` собирает отчёт сразу: `report.json` и `dashboard.html` в каталоге эксперимента (без имени: каждый эксперимент из `runs/`), печатает пути файлов. Нужны ключи рынка из `.env`; нет ключа или рынок недоступен: одна строка и код 1, неизвестный эксперимент: код 2. Для участника со счётом Alpaca команда сверяет журнал с исполненными заявками брокера (только чтение через API); если режим и брокер конфига не совпадают с записанными при старте, прогон ещё не обращался к брокеру или запрос не удался, сверка пропускается одной строкой, а отчёт строится ([[report-contents]]).
- `traider tick [--wiki DIR]` после обхода раз в день собирает тот же отчёт ([[tick-and-session]]). Шаблон launchd вызывает его без `--wiki`: на Mac mini статья вики не пишется и отслеживаемые файлы не меняются, иначе следующий `git push` будет отклонён. Статья `results-<эксперимент>` обновляется с машины разработки: `uv run traider report --wiki wiki` на машине, где лежат вики и копия `runs/` с Mac mini.

Если машина спит, HP не проверяется и недостающие стопы не выставляются ([[stops]], [[hp-floor]]). DAY-стопы действуют до закрытия, на следующий день их ставит первый тик ([[tick-and-session]]).

## Официальный прогон

Идёт там же, на Mac mini владельца. Вопрос о месте закрыт решением от 15.11.2026.

## Живой прогон

Только на постоянно включённой машине. С API-ключом это перенос без изменений кода ([[model-and-budget]]).

## Что не подходит

Vercel и похожие площадки для сайтов: боту нужны долгая работа и постоянный диск. Облачные сессии Claude Code по расписанию тоже отвергнуты ([[model-and-budget]]).

## Хранение

Файлы JSON и JSONL в папке прогона, без базы данных; папки `runs/` и `logs/` не попадают в репозиторий.
