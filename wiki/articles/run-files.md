# Файлы прогона

У каждого участника свой каталог `runs/<эксперимент>/<участник>/`. Читает и пишет его только модуль `RunStore`; брокеры, сессия и отчёт ходят в файлы через него. Журнал заявок это запись, которая должна пережить сбой.

| Файл | Что в нём |
|---|---|
| `orders.jsonl` | Журнал заявок, только дописывается. Строка на событие: номер `seq`, время `ts` (по умолчанию часы машины; `append_order` принимает необязательный `ts`, встроенный счёт передаёт время рынка), день, вид, тикер, сумма, количество, цена, стоп, тезис, причина отказа, идентификаторы заявки |
| `forecasts.jsonl` | Прогнозы: день, тикер, вероятность |
| `state.json` | Статус прогона, заметки, время последней сверки; у встроенного счёта ещё и сам счёт |
| `sessions/<день>.json` | Запись сессии дня: статус, время старта и итоги |
| `prices/<день>.json` | Снимок цен дня |

## Значения

- Вид события в журнале: `buy`, `close`, `raise_stop`, `stop_fill`, `liquidate`, `reject`.
- Статус сессии: `started`, `ok`, `cap`, `failed`, `missed`. Сессия, которая «started» дольше 30 минут, считается зависшей.
- Статус прогона: `active`, `finishing`, `finished`, `dead`, `invalid`. Планировщик берёт только `active` и `finishing`.

## Защита от сбоя

- Оборванная последняя строка журнала при чтении пропускается, следующая запись начинается с новой строки, номера `seq` продолжаются.
- Каждая запись журнала сбрасывается на диск сразу. Остальные JSON-файлы пишутся через временный файл и подмену, половина файла не остаётся.
- Сессия за день стартует только один раз: повторный старт получает отказ. Запись создаётся атомарно и эксклюзивно (из двух одновременных стартов выигрывает один), а повреждённый или пустой файл сессии читается как зависший старт со временем изменения файла, поэтому такой день попадёт в «зависшие» и не пропадёт.
- Строки журналов режутся только по символу новой строки, поэтому тезис с необычными разделителями строк не рвёт запись.
- Прогон с нечитаемым `state.json` планировщик считает активным, чтобы тик сообщил об ошибке по нему одному.
- Факты сессии для клетки ([[cage-rules]]: покупок за сессию, закрытые сегодня, прогнозы по панели) не хранятся, а считаются из журнала и прогнозов.
